# Sağlayıcıların özel bağlantı sınırları

Doğrulama: 3 Ekim 2026. Bu not birincil belgelerin ve protokol şekillerinin denetimidir; bu hesaplarda gerçek kimlik bilgileriyle inference çalıştırılmadı. Katalogda bulunmak, eklentide çalışan bir tarayıcı bağlantısı anlamına gelmez. SDK paket adından tek başına `openai-chat` protokolü çıkarılmamalı.

## Cloudflare ayrıntısı

Workers AI'nin [resmî OpenAI uyumluluğu](https://developers.cloudflare.com/workers-ai/configuration/open-ai-compatibility/) hesap kimliği içeren URL ve Cloudflare bearer token örneğini verir. Responses desteği aynı sayfada belirli GPT-OSS modelleriyle sınırlıdır; chat kataloğundaki her model için Responses varsayılmamalı.

[Gateway Unified API](https://developers.cloudflare.com/ai-gateway/usage/chat-completion/) iki kimlik düzenini ayırır: CF token ile saklanmış anahtar kullanımı; upstream bearer anahtarı ve gerektiğinde ayrı `cf-aig-authorization: Bearer <CF token>` ile istekte BYOK. [Unified Billing](https://developers.cloudflare.com/ai-gateway/features/unified-billing/) üçüncü taraf modelleri Cloudflare hesabı üzerinden ücretlendirebilir. Gateway adı/model prefix'i, upstream OpenAI model kimliğiyle karıştırılmamalı. Tek alanın hem CF token hem upstream token olduğu sessiz bir varsayım yapılmamalı.

Bu sayfa 2 Ekim 2026 güncellemesinde `/compat/chat/completions` yolunu yeni tek model entegrasyonları için deprecated olarak işaretler; mevcut entegrasyonların çalışmaya devam ettiğini belirtir. Yeni standart yol hesap altındaki `/ai/v1/chat/completions` adresidir. Compat kullanılırken upstream Anthropic/Responses SDK metadata'sı native yola çevrilmez: bütün model aileleri OpenAI chat gövdesiyle bu tek yola gider. Saklanmış BYOK örneği yalnız `cf-aig-authorization` başlığını da kabul eder.

## Bedrock ayrıntısı

[API anahtarı belgesi](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-use.html) Bedrock/Bedrock Runtime bearer anahtarını doğrular; Agents, Data Automation ve `InvokeModelWithBidirectionalStream` için kullanılamaz. [Chat Completions belgesi](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-chat-completions.html) runtime `/openai/v1` yolunu, ayrıca mantle `/v1` yolunu ve kimlik seçeneklerini verir. Runtime endpoint `GET /models` uygulamaz; model yenileme düğmesinin genel `/models` isteğini kullanması yanlış olur.

[Native Converse API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Converse.html) OpenAI body şekli kullanmaz: `system: [{text: ...}]`, `messages: [{role: 'user', content: [{text: ...}]}]`, `inferenceConfig`; çıktı `output.message.content[].text` içindedir. Model ID/ARN/inference-profile kimliği URL path segmenti olarak kodlanmalı. Bearer anahtarıyla native Converse desteklemek, SDK'nın AWS profil/SSO veya SigV4 kimlik akışlarını desteklemek anlamına gelmez.

## Snowflake, SAP ve IBM

[Snowflake Cortex REST API](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-rest-api) OpenAI uyumlu chat ve Anthropic uyumlu messages protokollerini ayrı yollarla belgeler. PAT/JWT/OAuth aynı Bearer başlığını kullanabilir; isteğe bağlı `X-Snowflake-Authorization-Token-Type` token türünü netleştirir. Hesap URL'si, model erişimi ve Snowflake hesabındaki yetkiler gerekir. Snowflake tarayıcı SSO/OAuth token yenilemesi ayrıca uygulanmalıdır.

[SAP model tüketimi](https://help.sap.com/docs/sap-ai-core/sap-ai-core-service-guide/consume-generative-ai-models-using-sap-ai-core) deployment URL ve resource-group başlığını zorunlu bağlam olarak tanımlar. [SAP token edinimi](https://help.sap.com/docs/sap-ai-core/sap-ai-core-service-guide/get-auth-token?locale=en-us) hizmet anahtarındaki auth URL'ye `/oauth/token` eklenmesini, form gövdesinde `grant_type=client_credentials`, `client_id`, `client_secret` gönderilmesini belgeler. [Service key kullanımı](https://help.sap.com/docs/ai-core/ai-core/use-service-key) Basic authorization yöntemini de gösterir; X.509 anahtarlar ise sertifika/key/certUrl ile ayrı mTLS akışı gerektirir. [SAP OpenAI deployment örnekleri](https://help.sap.com/docs/sap-ai-core/generative-ai/openai) model ailesine göre `api-version` değerlerini gösterir. Model adı service key'in yerine geçmez; her SAP deployment OpenAI chat değildir.

[IBM IAM token API](https://cloud.ibm.com/apidocs/iam-identity-token-api) API key'i `https://iam.cloud.ibm.com/identity/token` adresine form body içinde `grant_type=urn:ibm:params:oauth:grant-type:apikey` ile gönderir. Inference bearer alanında dönen access token kullanılır. [watsonx.ai API dizini](https://cloud.ibm.com/docs/apis/watsonx-ai) `/ml/v1/text/chat`, `/ml/v1/chat/completions` ve deployment chat yollarını ayrı listeler; [watsonx Developer access](https://dataplatform.cloud.ibm.com/docs/content/wsj/analyze-data/fm-api.html?context=wx&locale=en) servis URL'si ve project/space ID'yi sağlar. [IBM Inference ürünü](https://cloud.ibm.com/docs/inference?topic=inference-inference) ise `/v1/projects/{project}/inference/chat/completions` kullanır. Bu farklı ürünler tek URL varsayımıyla birleştirilmemeli.

[IBM native chat şeması](https://ibm.github.io/watsonx-ai-node-sdk/interfaces/1_7_x.WatsonXAI.TextChatParams.html) `model_id`, `messages` ve yalnız bir `project_id`/`space_id` bağlamını ister. İstek tarihli `version=YYYY-MM-DD` kullanır; `max_tokens` geçerlidir, daha yeni `max_completion_tokens` alanı da vardır. Token ve inference adresleri farklı origin ise ikisinin izni ilk kimlik isteğinden önce kontrol edilmelidir. SAP için aynı kural client secret'a uygulanır. Token süreleri ürün/hizmete göre değişir; örnekteki süreden kalıcı token sonucu çıkarılmaz.

[IBM system message](https://ibm.github.io/watsonx-ai-node-sdk/interfaces/1_7_x.TextChatMessageSystem.html) `content` değerini string olarak tanımlar; kullanıcı mesajı metin parçaları kullanabilir. Eklentinin `watsonx-chat` dalı bu ayrımı korur. IBM Cloud IAM anahtarı her işlemde yenilenir ve access token yalnız işlem belleğinde tutulur; software/CP4D veya ayrı IBM Inference/deployment ürünlerinin kimlik sözleşmesi bu testin kapsamında değildir.

[SAP Orchestration V2](https://sap.github.io/ai-sdk/docs/python/examples/orchestration-service2) model ailelerini `config.modules.prompt_templating` ile seçer, `placeholder_values` kullanır ve `final_result.choices` döndürür. [V2 completion yolu](https://help.sap.com/docs/sap-ai-core/generative-ai/use-orchestration-config-in-llm-orchestration) deployment URL'sine `/v2/completion` eklenir. Eklentinin varsayılan SAP taşıması bu orkestrasyon yoludur; ayrıca yalnız uygun OpenAI deployment için OpenAI chat yolu seçilebilir. X.509/mTLS servis anahtarları uygulanmadı. Bu seçimler modelin kullanıcının hesabında/deployment'ında açıldığını kanıtlamaz.

## Azure Claude ve Google Vertex

[Claude in Microsoft Foundry](https://platform.claude.com/docs/en/build-with-claude/claude-in-microsoft-foundry) Azure anahtarı için hem `api-key` hem `x-api-key` başlığını kabul eder. Yol `https://{resource}.services.ai.azure.com/anthropic/v1/messages`; Anthropic sürüm başlığı kullanılır. Azure OpenAI'nin `api-version` query'si ve `/openai/deployments/...` yolu bu Claude transportuna uygulanmaz. İstek `model` alanında Azure deployment adını kullanır. Foundry Models API desteklemez; model listesinde katalog fallback gerekir. Entra Bearer token almak/yenilemek ayrıca kimlik akışıdır.

[Azure model inference REST](https://learn.microsoft.com/en-us/rest/api/microsoftfoundry/model-inference/get-chat-completions/get-chat-completions?view=rest-microsoftfoundry-model-inference-2024-05-01-preview) eski `/models/chat/completions` yolunda `api-version` ister. [Resmî OpenAI migration](https://learn.microsoft.com/en-us/azure/foundry/how-to/model-inference-to-openai-migration) artık Azure AI Inference SDK'nın emekli olduğunu, DeepSeek/Grok gibi Foundry modellerinin de `https://{resource}.openai.azure.com/openai/v1/` yoluna taşınabildiğini belirtir. Katalogdan gelen `/models` metadata'sını version olmadan göndermek doğru değildir; yeni OpenAI v1 yolu veya açık legacy sürüm adaptörü kullanılmalıdır.

[Vertex Claude örnekleri](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/use-claude?hl=en) proje/konum/publisher kökünden `models/{model}:rawPredict` yolunu ve `anthropic_version: vertex-2023-10-16` gövdesini tanımlar. [Çok bölgeli uç noktalar](https://cloud.google.com/blog/products/ai-machine-learning/multi-region-endpoints-for-claude-available-on-vertex-ai/) farklı sunucu ve konum seçeneklerini açıklar. Katalogdaki tam publisher/endpoints kökünün ardından proje/konum yolunu ikinci kez eklememek gerekir. Native Gemini `generateContent`, Claude `rawPredict` ve MaaS OpenAI chat birbirinden ayrı taşımalardır; konum/bölge UI alanıyla resolver aynı değeri kullanmalıdır.

[MaaS OpenAI chat örnekleri](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/maas/call-open-model-apis?hl=en) ilk mesajın `user` olmasını ve `user`/`assistant` rollerini belgeler. Özel MaaS adaptöründe talimatı ilk kullanıcı mesajıyla birleştirmek bu belgeli sözleşmeyi izler; generic OpenAI'nin ilk `system` mesajını otomatik desteklenmiş saymak doğru değildir.

## Abonelik kimlikleri

[Copilot SDK mimarisi](https://github.com/github/copilot-sdk) CLI server + JSON-RPC katmanını doğrular. Bazı SDK'lar CLI'yi paketlese de yerel süreç gereksinimi devam eder. [Copilot kimlik belgesi](https://docs.github.com/en/copilot/how-tos/copilot-sdk/auth/authenticate) OAuth/GitHub App kullanıcı token'ı ile fine-grained PAT'i kabul eder; classic PAT kabul etmez. [Üçüncü taraf OAuth uygulaması](https://docs.github.com/en/copilot/how-tos/copilot-sdk/setup/github-oauth) ürün adına uygulama kaydı, client kimliği ve redirect/token akışını gerektirir. Eksik olan, doğrulanmış Chrome/native runtime bağlantısı ve ürünün kendi giriş akışıdır; OAuth'un teorik olarak yapılamadığı veya yalnız OAuth token'ının mümkün olduğu iddia edilmez.

[GitLab Duo Chat REST API](https://docs.gitlab.com/api/chat/) `POST /api/v4/chat/completions`, Bearer token ve `{content: ...}` ile string yanıtı belgeler; GitLab.com'da internal-only, Self-Managed'da `access_rest_chat` feature flag'i ve belgede GitLab team member önkoşulu vardır. Bu, genel OpenAI chat body/response sözleşmesi değildir. [Duo Agent Platform auth zinciri](https://docs.gitlab.com/user/duo_agent_platform/authentication/) kısa ömürlü JWT katmanlarını tanımlar. [Flows API](https://docs.gitlab.com/api/duo_agent_platform_flows/) PAT ile geliştirici iş akışı başlatabilir; workflow kimliği/durumu ve proje/namespace bağlamı döndürür. Bunların Chrome için bir correction adaptörü ayrıca uygulanıp doğrulanmalıdır.

[v0 v2 belgeleri](https://v0.app/docs/api/v2) uygulama üretme API'sini tanımlar. [v1→v2 migration](https://v0.app/docs/api/v2/guides/migrating-from-v1-to-v2) VM tabanlı chat durumu ve dosya iş akışını, yalnız final metin yerine message `parts` işlenmesini ister. [Resmî web arayüzü örneği](https://v0.app/docs/api/v2/guides/custom-chat-interface) tarayıcıdan ürünün backend'ine erişir; gizli v0 anahtarı server SDK'da tutulur. Eklentide bu ürün için genel metin düzeltme adaptörü doğrulanmadı. API bulunmadığı veya eski chat-completions adresinin kesin kapandığı iddia edilmez; bu adresin eski belgesi güncel v1 sayfasına yönlenmiştir.

## Önerilen deterministik testler

- Gateway'de stored-key ve request-BYOK header'larını iki ayrı fixture ile kontrol edin; iki token'ın karışması veya başka hosta aktarılması reddedilsin.
- Workers AI hesap ID'si, gateway ID'si, region ve Snowflake hesap URL'si eksikken inference başlamasın.
- Tüm seçilebilir katalog modelleriyle resolver/request builder çalıştırın; kalan URL placeholder'ı, iki kez proje/konum yolu ve model ailesine aykırı endpoint reddedilsin. Bu denetim gerçek hesap/çıkarım desteğinin kanıtı değildir.
- Bedrock native Converse ile OpenAI body/response örneklerini birbirinden ayırın; IAM anahtarını bearer gibi kabul etmeyin; `/models` desteğini varsaymayın.
- SAP/IBM token ve inference origin izinleri birlikte kontrol edilsin; biri yoksa token isteği de yapılmasın. Boş/bozuk/süresi dolmuş token ve token endpoint hataları kullanıcı metni veya client secret sızdırmadan açıklansın.
- SAP client secret ve IBM API key; token/inference URL host/path/query, model ve deployment alanlarında bulunursa gönderim reddedilsin. Dönen access token da inference URL'ye sızmasın.
- Copilot/Duo OAuth/runtime taşınmadıysa katalog durumu bunu açık göstermeli ve kullanıcı anahtarı/metni yanlış endpoint'e gitmemeli.
- Anahtar, metin ve özel promptu hata body/URL/loga eklemeyin; kimlik bilgisi taşıyan istekte redirect izlemeyin.
